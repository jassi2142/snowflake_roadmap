# Unstructured Data

Unstructured data is information that does not fit a predefined schema: documents, PDFs, images, audio, video, and industry-specific file formats. Snowflake lets you store and govern these files in stages, generate secure URLs to share them, catalog them alongside structured data, and process them with SQL, UDFs, stored procedures, and Snowpark.

## How it works

**Storage.** Files live in stages. Both internal stages (Snowflake-managed) and external stages (Amazon S3, Google Cloud Storage, Azure Blob Storage, and Data Lake Storage Gen2) support unstructured data.

**Encryption matters for internal stages.** By default, internal stage files are client-side encrypted with Snowflake-owned keys, which makes them unreadable through file, scoped, or pre-signed URLs. To serve files via URLs, create the stage with `ENCRYPTION = (TYPE = 'SNOWFLAKE_SSE')`. The encryption type cannot be changed after creation, and `SNOWFLAKE_SSE` does not support Tri-Secret Secure.

**Three URL types:**

| URL type | Generated by | Who can use it | Expiration |
| --- | --- | --- | --- |
| Scoped URL | `BUILD_SCOPED_FILE_URL` | Only the user who generated it | When the persisted query result period ends (currently 24 hours) |
| File URL | Directory table `FILE_URL` or `BUILD_STAGE_FILE_URL` | Roles with READ (internal) or USAGE (external) on the stage | Permanent |
| Pre-signed URL | `GET_PRESIGNED_URL` | Anyone holding the URL | Configurable expiration time |

Scoped URLs are recommended for giving governed access through a view: only roles with access to the view can retrieve them, and file access is recorded in query history. Scoped and pre-signed URLs can be exposed to consumers through secure views in a share; file URLs cannot.

**Cataloging.** Directory tables store file-level metadata (path, size, last modified, MD5, ETag, file URL) and can be joined with business tables to build views over files.

**Processing.** You can read files in Java or Python UDFs, UDTFs, and stored procedures (including via Snowpark), or call external services through external functions. The **FILE** data type represents a staged file; `TO_FILE` and `TRY_TO_FILE` create FILE values that some built-in functions accept in place of a stage name and path.

## Example

Create an internal stage that supports URL access and has a directory table:

```sql
CREATE STAGE docs_stage
  ENCRYPTION = (TYPE = 'SNOWFLAKE_SSE')
  DIRECTORY = (ENABLE = TRUE);
```

After uploading files (for example with `PUT` from Snowflake CLI), refresh and list them:

```sql
ALTER STAGE docs_stage REFRESH;

SELECT relative_path, size, last_modified
FROM DIRECTORY(@docs_stage);
```

Generate URLs of each type:

```sql
SELECT BUILD_SCOPED_FILE_URL(@docs_stage, 'contracts/acme.pdf')  AS scoped_url,
       BUILD_STAGE_FILE_URL(@docs_stage, 'contracts/acme.pdf')   AS file_url,
       GET_PRESIGNED_URL(@docs_stage, 'contracts/acme.pdf', 3600) AS presigned_url;
```

Expose governed access to a subset of files through a view:

```sql
CREATE OR REPLACE SECURE VIEW legal_contracts AS
SELECT relative_path,
       BUILD_SCOPED_FILE_URL(@docs_stage, relative_path) AS url
FROM DIRECTORY(@docs_stage)
WHERE relative_path LIKE 'contracts/%';

GRANT SELECT ON VIEW legal_contracts TO ROLE legal_reader;
```

## Best practices

- Decide on server-side encryption when you create an internal stage; it cannot be changed later.
- Prefer scoped URLs behind views for internal users and shares; use pre-signed URLs only when unauthenticated access is truly required, with short expirations.
- Organize files with meaningful path prefixes so you can filter, refresh, and grant by area.
- Store extracted metadata or text in tables so downstream queries do not reprocess files.
- Use directory tables as the inventory for processing pipelines.

## Common pitfalls

- Uploading files to a default-encrypted internal stage and finding that URLs return unreadable content.
- Sharing pre-signed URLs with long expirations, which grant access to anyone who has the link.
- Expecting scoped URLs to work for other users or after the result cache period ends.
- Forgetting to refresh the directory table, so new files are missing from listings.

## Knowledge check

### A BI tool must display images to users who do not authenticate to Snowflake. Which URL type fits?
- [ ] Scoped URL
- [ ] File URL
- [x] Pre-signed URL
- [ ] Stage location URL
> Pre-signed URLs can be opened by anyone holding them for the life of the token, without a Snowflake authorization token.

### Files on an internal stage download as unreadable content through file URLs. What is the likely cause?
- [ ] The directory table is disabled
- [x] The stage uses default client-side encryption instead of SNOWFLAKE_SSE
- [ ] The files are larger than 128 MB
- [ ] The warehouse is suspended
> Internal stages are client-side encrypted by default with Snowflake-owned keys; URL access requires a stage created with server-side encryption.

### You want only members of a specific role to retrieve certain staged files, with access recorded in query history. What is the recommended approach?
- [ ] Email pre-signed URLs with a 7-day expiration
- [x] Expose scoped URLs through a view granted to that role
- [ ] Grant WRITE on the stage to the role
- [ ] Publish file URLs in a share
> Scoped URLs in a view restrict access to roles with privileges on the view, and Snowflake records who used them.
